> [!IMPORTANT]
> GPU Shark работает строго в режиме только для чтения. Он не изменяет частоты,
> напряжение, прошивку или управление вентиляторами и не устанавливает драйвер
> ядра.

GPU Shark — лёгкое Win32-приложение без браузерного движка, тяжёлого GUI-фреймворка и скрытой фоновой телеметрии. Оно показывает только те параметры, которые действительно предоставляет оборудование и драйвер. Недоступные датчики скрываются вместо того, чтобы подменяться рассчитанными или предположительными значениями.[^sensor-availability]

![Панель датчиков GPU Shark](materials/213.png)

## Кратко

| Нативно и легко | Честная телеметрия | Полезно во время тестирования |
|---|---|---|
| Быстрый Win32-интерфейс и официальный портативный single-EXE | Core, HotSpot и VRAM никогда не подменяются друг другом | История в реальном времени, максимумы за сессию и причины PerfCap, совместимые с GPU-Z |
| Панель без мерцания с обновлением раз в секунду и настраиваемым интервалом | Расширенные температурные маппинги включаются только для проверенных PCI-профилей | Отдельные показания вентиляторов, мощности, напряжения, активности и системных параметров при их наличии |
| Английский язык по умолчанию, русский интерфейс и выбор акцентного цвета | Отсутствующие или неподдерживаемые измерения скрываются | Отправка обратной связи по неизвестным видеокартам и ошибкам провайдера только с согласия пользователя |

### Возможности

- Температуры GPU Core, HotSpot и VRAM, если они доступны на конкретном оборудовании
- Расшифровка причин NVIDIA PerfCap, совместимая с GPU-Z: <code>Pwr</code>,
  <code>Thrm</code>, <code>VRel</code>, <code>VOp</code>, <code>Idle</code>
  и <code>SLI</code>
- Отдельные значения RPM для нескольких вентиляторов на поддерживаемых платах
- Датчики мощности и напряжения GPU, платы и источника питания
- График выбранного датчика в реальном времени
- Отслеживание максимального значения для каждого датчика, включаемое двойным щелчком по строке
- Сохранение настроек языка, интервала обновления и акцентного цвета
- Форма обратной связи с обязательным согласием пользователя и без автоматической отправки
- Фиксированный горизонтальный интерфейс с двойной буферизацией и отрисовкой без мерцания

## Поддержка GPU

Стандартный путь через драйвер и провайдер работает со многими видеокартами NVIDIA, однако точный набор доступных датчиков зависит от GPU, дизайна платы, драйвера и прошивки. Расширенная поддержка температур намеренно отслеживается отдельно для каждого проверенного профиля устройства.[^sensor-availability]

> [!WARNING]
> Поддержка HotSpot на GeForce RTX 50-й серии находится в статусе **бета**.
> Текущий проверенный расширенный профиль — настольная GeForce RTX 5050
> (10DE:2D83); остальные RTX 50 остаются в консервативном режиме, пока не
> будут подтверждены их точные аппаратные профили. GPU Shark помечает любую
> отображаемую строку HotSpot на RTX 50 как <code>БЕТА</code>. Эта отметка не
> создаёт отсутствующее значение.

| GPU | Core | HotSpot | Температура VRAM | Статус профиля |
|---|:---:|:---:|:---:|---|
| GeForce RTX 2060 SUPER | Да | Проверено | Зависит от платы | Проверено |
| GeForce RTX 2070 SUPER | Да | Проверено | Проверено | Проверено |
| GeForce RTX 3050 | Да | Проверено | Зависит от платы | Проверено |
| GeForce RTX 3060 | Да | Проверено | Зависит от платы | Проверено |
| GeForce RTX 3070 | Да | Проверено | Зависит от платы | Проверено |
| GeForce RTX 3080 | Да | Проверено | Проверено | Проверено |
| GeForce RTX 4060 | Да | Проверено | Зависит от платы | Проверено |
| GeForce RTX 4090 | Да | Проверено | В процессе проверки | HotSpot проверен |
| GeForce RTX 5050 | Да | Бета[^rtx50] | Проверено | Точный настольный профиль |
| GeForce RTX 5070 | Да | В работе[^rtx50] | Да на протестированной плате | Экспериментально |
| GeForce RTX 5070 Ti | Да | В работе[^rtx50] | Да на протестированной плате | Экспериментально |
| Другие NVIDIA GPU | Обычно | Зависит от драйвера/платы | Зависит от драйвера/платы | Консервативный fallback |

Пользовательская таблица поддержки находится в [SUPPORTED_GPUS.md](SUPPORTED_GPUS.md).
Если измерение невозможно достоверно подтвердить, GPU Shark оставляет его недоступным.

Поддержка AMD GPU пока остаётся только долгосрочной идеей: активной реализации или сроков релиза на данный момент нет.

## Скачивание

1. Откройте [страницу релизов](https://github.com/k1gs/Gpu-Shark/releases).
2. Скачайте <code>GPU-Shark-win-x64.zip</code> и
   <code>SHA256SUMS.txt</code> из последнего релиза.
3. Сверьте SHA-256 архива, распакуйте его и запустите
   <code>GPU-Shark.exe</code>.
4. Подтвердите запрос Windows на права администратора, необходимые для локального
   доступа к аппаратной телеметрии в режиме только для чтения.

~~~powershell
(Get-FileHash .\GPU-Shark-win-x64.zip -Algorithm SHA256).Hash
~~~

Официальный пакет содержит автономный исполняемый файл. Windows SmartScreen может показывать предупреждение, поскольку текущие бинарные файлы не имеют цифровой подписи. Скачивайте GPU Shark только из этого репозитория и проверяйте опубликованный хэш.

### Требования

- Windows 10 или Windows 11, x64
- NVIDIA GPU с установленным драйвером
- Права администратора для локального доступа к оборудованию

## Обратная связь и конфиденциальность

Приложение никогда не отправляет отчёты автоматически. Обратная связь отправляется только после того, как пользователь вводит сообщение и явно подтверждает согласие на отправку.

Отчёт может содержать версию приложения, выбранный язык интерфейса, название обнаруженной видеокарты, текущие отображаемые публичные датчики, безопасное описание ошибки провайдера, сообщение пользователя и необязательный адрес для ответа.

Отчёты не содержат UUID видеокарты, серийные номера, имя компьютера, имя учётной записи Windows или приватные аппаратные диагностические данные.

> [!CAUTION]
> Не прикладывайте к публичным Issues или Pull Requests приватные диагностические
> дампы, закрытые материалы NVIDIA, секреты API или снимки экрана и логи,
> содержащие идентифицирующие данные.

## Сборка публичного GUI

Исходный код публичного GUI на Rust/Win32 находится в [gui-source/](gui-source/). Реализации управляемого и нативного телеметрических провайдеров намеренно не публикуются.

Соответствующие публичные runtime-DLL поставляются в составе релизного архива
<code>GPU-Shark-gui-runtime-win-x64.zip</code>.[^official-build]

### Требования для сборки

- Стабильный Rust toolchain с <code>rustfmt</code>
- Visual Studio C++ Build Tools
- Runtime-архив, соответствующий версии GUI

### Локальная сборка

1. Скачайте соответствующий runtime-архив и извлеките из него DLL.
2. Откройте PowerShell в каталоге <code>gui-source/</code>.
3. Настройте совместимый адрес для отправки обратной связи. Production-адрес не хранится в публичном исходном коде.
4. Выполните форматирование, тестирование и сборку GUI.
5. Поместите runtime-DLL рядом с получившимся исполняемым файлом.

~~~powershell
$env:GPU_SHARK_FEEDBACK_HOST = "your-compatible-feedback-host"
$env:GPU_SHARK_FEEDBACK_PATH = "/your/api/path"

cargo fmt --check
cargo test
cargo build --release --locked

Copy-Item C:\path\to\runtime\*.dll .\target\release\
.\target\release\gpu-shark-gui.exe
~~~

GUI загружает <code>gs.dll</code>, расположенную рядом с исполняемым файлом, и вызывает небольшой публичный экспорт <code>q</code>, чтобы получить один JSON-снимок телеметрии, очищенный от приватных данных.

Версии runtime и GUI должны совпадать.

### Сборка через GitHub Actions

Workflow [Build public GUI](.github/workflows/gui-build.yml) форматирует, проверяет и собирает GUI, скачивает соответствующий runtime, проверяет его опубликованный SHA-256 и загружает готовый к запуску CI-артефакт.

Workflow имеет только права на чтение репозитория и не может публиковать или изменять релизы.

## Участие в разработке

Небольшие и сфокусированные Pull Request приветствуются. По возможности отделяйте изменения реализации, документации и системы сборки в разные коммиты.

### Ветки и коммиты

~~~powershell
git checkout -b feat/short-description

cargo fmt --check
cargo test
cargo check --locked

git add path\to\changed-file
git diff --cached
git commit -m "feat: describe the user-visible change"
git push -u origin feat/short-description
~~~

Открывайте Pull Request в ветку <code>main</code> и указывайте:

- что было изменено и зачем;
- как изменение тестировалось;
- какая видеокарта и версия драйвера использовались при проверке аппаратно-зависимого поведения;
- влияет ли изменение на конфиденциальность, упаковку приложения или публичный ABI.

| Префикс | Для чего использовать |
|---|---|
| <code>feat:</code> | Новая пользовательская функциональность |
| <code>fix:</code> | Исправления ошибок и регрессий |
| <code>docs:</code> | Изменения только документации |
| <code>test:</code> | Тесты и fixtures |
| <code>build:</code> | Сборка, упаковка и CI |
| <code>refactor:</code> | Внутренняя переработка без изменения поведения |

> [!WARNING]
> Никогда не распространяйте температурный маппинг, полученный на одной плате,
> на всё семейство GPU. Новые маппинги HotSpot или VRAM требуют точного
> PCI-профиля и независимого подтверждения. Не публикуйте приватные исходники
> провайдера, приватные идентификаторы API, сырые дампы, debug symbols или данные
> локальной машины.

## Лицензия

Оригинальный код GPU Shark и релизные бинарные файлы распространяются по
[лицензии Beerware](LICENSE). Сторонние компоненты сохраняют свои собственные
лицензии; соответствующие уведомления включаются в каждый бинарный/runtime-релиз.

Сообщения об ошибках принимаются через [GitHub Issues](https://github.com/k1gs/Gpu-Shark/issues).

[^sensor-availability]: Доступность датчиков различается в зависимости от GPU,
    производителя и дизайна платы, версии драйвера и прошивки. Наличие модели
    видеокарты в таблице не означает, что каждая её версия предоставляет все
    указанные измерения.
[^rtx50]: Поддержка HotSpot на RTX 50 находится в бета-стадии и открывается
    только при наличии доказательств. Для настольной RTX 5050 10DE:2D83
    подтвержден независимый путь HotSpot; остальные RTX 50 остаются без него,
    пока не получат собственные доказательства на точно такой же плате.
    Значения Core или VRAM никогда не будут переименованы в HotSpot.
[^stress-test]: Любой будущий стресс-тест должен явно запускаться пользователем
    и оставаться полностью изолированным от управления частотами, напряжением,
    прошивкой и вентиляторами.
[^official-build]: Публичный исходный код позволяет собрать и проверить GUI с
    соответствующим выпущенным runtime. Для воспроизведения официального
    автономного EXE также требуется приватный pipeline сборки провайдера,
    который намеренно находится за пределами публичного репозитория.
